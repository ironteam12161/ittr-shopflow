# ITTR ShopFlow: button, action and UX audit (2026-10-10, v24.41.7)

## 1. Method

| Check | What it covered | Result |
|---|---|---|
| Static handler check | All 470 inline `onclick` / `onchange` / `onsubmit` handlers in `index.html` and every module must call a function that exists | 470/470 resolve |
| Whole-script call check | Every function call in the front-end scripts must resolve | 1 call to a missing function, 2 calls to a function that was never defined (but guarded) (fixed, §2) |
| Automated click-through | A robot logged in as **owner**, **manager** and **mechanic** at desktop (1440 px) and phone (390 px) width. On every page it pressed every visible button, tab and tile one by one, including the buttons inside each pop-up, and recorded JS errors, failed API calls, alert boxes and buttons that did nothing. Anything destructive or outward-facing was skipped and every "are you sure?" was cancelled (delete, void, send, reset, clock, payments) | owner 313 presses, manager 303, mechanic 22: 0 JavaScript errors. Manager: 18 permission errors (fixed). "Dead" buttons: only submit buttons stopped by the browser's "please fill out this field" check, which is expected |
| Screens | About 120 screenshots of pages and pop-ups were reviewed by hand | See §3 and §4 |

## 2. Bugs fixed in this release

| # | Severity | Problem | Fix |
|---|---|---|---|
| 1 | High | **Manager accounts were invisible.** Team Accounts listed only mechanics, so a manager could be created but never seen, edited, have their password reset, or be deleted. After you created one, the screen also showed "loadStaffAccounts is not defined", because the page called a function that didn't exist. | Managers are now listed with their permissions and **Permissions / Change Password / Delete** buttons. New `GET /api/admin/managers` and `PATCH /api/admin/managers/:username/password` (owner only). A password change signs the manager out everywhere. |
| 2 | High | **Managers got "access denied" (403)** when opening a work order's timer history, and could not add or remove helper mechanics ("You must already be assigned…"). | Managers have the same access as the owner on these three actions. |
| 3 | Medium (data) | Inspection **"+ Add to work order"** and **inspection PDF** tried to save the mechanic's latest marks first through `syncNow()`, which was never defined. If the last tap hadn't reached the server yet, the server worked from older marks. | `syncNow()` now waits until the latest save has reached the server (up to 5 s). |
| 4 | Medium | The Create Manager form accepted an 8-character password, but the server requires 12. The form failed only after everything was filled in. | The form requires 12 and says so. |
| 5 | Medium (UX) | Day / Week / Month calendar buttons all looked selected. | Only the current view is filled. |
| 6 | Medium (UX) | A job timer left running for days (for example 241 h) showed as a normal green "Working" card. | Timers over 12 h turn the card orange with "Timer running over 12 hours. Did they forget to pause it?" |
| 7 | Medium (phone) | The Work Orders list was a wide table that needed sideways scrolling on phones. Scheduled, Mechanic and Status were cut off. | On phones each work order is a stacked card with labels. |
| 8 | Low (UX) | In Create / Edit Work Order, checkboxes sat on a separate line from their labels. "Fleet unit automatically visible" showed for customer trucks too. | Checkboxes are inline with larger boxes. Only the checkbox for the chosen unit type is shown. The date defaults to today. |
| 9 | Low | Completed Jobs showed a raw timestamp (`2026-10-10T15:33:22.139Z`). | Shown as a normal date and time. |
| 10 | Low | The work order pop-up showed an empty "Priority:". | Shows "Normal" when none is set. |
| 11 | Low | The green build banner took three lines on phones, for every user including mechanics. | Shown only to the owner, on one line. |
| 12 | Low | Mechanic screen: "Update Activity" with nothing picked, and "Add helper" when everyone is already assigned, popped a browser alert box. | Short on-screen messages instead. Activity history now reads "7:05 PM / to 7:35 PM". |

## 3. Recommended next steps (not changed yet; for your decision)

### Navigation and naming
1. **One name per page.** The nav says **Findings** but the page title is "Findings Center". **Operations** opens "Shop Operations", **Compliance** opens "Fleet & Compliance", and "Truck Search" is reached as Unit History. Use the nav word as the page title so people always know where they are.
2. **Header icons.** The checkbox labeled **AI** in the header isn't obvious. Rename it "AI help on/off" with a tooltip, or move it into Operations → AI tools. The **Live** dot is grey and tiny; make it say "Live" (green) or "Offline – changes saved on this device" (orange).
3. **Workshop AI button** floats over the bottom-right of every page and covers table buttons ("Open", "Export CSV") on smaller laptops and phones. Make it a small round icon, or move it into the header.

### Work orders
4. **Two status columns that can disagree.** The list shows *Availability* ("Waiting for Truck") next to *Status* ("Being worked on"), for example WO #2003. Merge them into one stage pill: Scheduled → Truck here → In progress → Paused → Done. Show the "truck not here yet" warning only when it matters.
5. The **Parking** column is "—" on every row. Hide the column when no work order has a spot, or show it inside the unit cell.
6. Add a **search box and a mechanic filter** above the Work Orders list (the Invoices page has a good pattern to copy).

### Invoices and money
7. The invoice **status pills** (DRAFT, SENT, PARTIAL, PAID, OVERDUE) should use the same colors everywhere: grey draft, blue sent, amber partial, green paid, red overdue. Show the overdue days, for example "Overdue 12 d".
8. The KPI cards mix counts and dollars: "Paid 51" is a count next to "$10,395" amounts. Show dollars with the count underneath, the way the Estimates cards already do.
9. **Stripe online payments** still aren't marked paid automatically, and emailing an invoice doesn't mark it "Sent" (carried over from the 2026-09-30 audit).

### Mechanic screen (phone)
10. The header (Back, logo, language, Logout) takes about 150 px before any work is visible. Use one compact row: logo · EN · ⎋.
11. Order the screen by priority: **Time Clock** → **current job timer** (big Pause / Complete) → **Ready to Work** list → Activity tiles. Activity tiles are rarely used compared to job timers but currently sit above the job list.
12. "Inspection" in the mechanic nav opens "Inspection / Needs Attention" (findings), not the truck inspection checklist. Rename it **Findings** to match the admin side.

### Consistency and accessibility
13. Buttons use about five different heights (30–64 px) and three blues. Standard: 44 px main buttons, 36 px in tables, one primary blue, red only for destructive actions, and the destructive button always last and spaced away from the others ("Delete Work Order" currently sits next to "Edit Full Work Order").
14. Many inputs rely on placeholders as labels ("Part Number", "Part Description" in the work order pop-up). Placeholders disappear when you type; add small labels.
15. Pop-ups: close with Esc everywhere (most do), keep the primary action at bottom-right, and keep the ✕ in the same corner.
16. Dates appear as `2026-09-30`, `Sep 30, 2026` and `9/30/2026` on different pages. Pick one (for example "Sep 30, 2026") and one time format.
17. Empty states ("No customers found.") should say what to do next, for example "No customers yet. Import from Fullbay (Operations → Fullbay & Samsara) or + Add Customer."

### Data hygiene
18. Test data from before go-live (LAB-* invoices, old running timers, test mechanics) should be cleared with **Operations → Start fresh** before real use. The 241-hour timer on the dashboard is an example.
